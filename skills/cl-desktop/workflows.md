# Whole-Desktop Workflow Verification

The router joins owning skills; it is not another command framework. Completion requires an observable final state, not a larger catalog.

| Core workflow ID | Verify | Evidence surface |
|---|---|---|
| `transport-discovery` | Fresh private discovery → bounded liveness/auth/origin → intended tab → authoritative renderer commands/version → project hydration and save readiness. Legacy manifests remain unverified. | `cl-editor/workflow-readiness.md`, targeted `/api/capabilities`, `query.getProjectReadiness`, `GET /api/tabs`. |
| `transport-safe-outcomes` | JSON mutation/upload succeeds with a verified response, or reports an uncertain outcome **without** automatic replay. Reconcile native saved state before retrying. | Owning domain manifest/status; native publishing attempt/post records; scoped upload receipts. |
| `transport-distribution` | Public master/domain routers load from the installed bundle or canonical checkout; new loader links do not overwrite independent directories; helper absence yields concrete installation guidance. | `/api/skills` provenance/partial/errors/installation, canonical `SKILLS_MAP.md`, public bundle hash manifest. |

## Verify the chain, not just individual commands

1. Research produces a saved/reviewed brief or reference, not an unexplained scrape.
2. Production produces the intended project/canvas, preview-verified media and a current-design save receipt.
3. Rendering produces a verified output file and completed native job; failures/cancellation are inspected explicitly.
4. Publishing produces a native saved attempt/post and status. Provider acceptance followed by persistence failure is not safe to resubmit blindly.
5. Offers/checkout produce the intended draft/published state. Buyer mandate/payment consent is separate from preparing a checkout URL.
6. CRM imports/bulk changes preserve ownership, expected revisions and per-item outcomes; exports are complete within their explicit bounds.
7. Calls/Webinars/Deals preserve recipient/operator/role/financial approval. Inspect their saved lifecycle state after any partial failure.
8. Deals attachments up to512MiB preserve exact creative/thread/file approval; larger-than10MiB uploads return a local job. Inspect its attachment receipt, explicitly reconcile uncertain commits without resending bytes, and then separately save/send. Cancellation never promises remote rollback; local jobs do not survive restart.
9. Boards PDF imports use selected local PDF registration or an approved source URL, exact page review, bounded rendering/upload, explicit apply and separate save. First-ever creator onboarding claims a handle through the reviewed native route before handle-scoped surface commands.

Read each owning skill for exact payloads, limits and remaining product gaps. A missing command adapter is **missing**, not “human-required” merely because the UI has a button. Genuine OAuth, payment, microphone and consent steps are human-required. Do not infer universal workflow coverage from command-name counts or source-only validation.

## Phase-3 verification extensions

- Purchases → exact delivery → approved reaccess → token contents → approved
  private file resolution: preserve entitlement/native errors and private URLs.
  Seller lead → delivery → approved resend/revoke has real messaging/access effects.
- Affiliate configuration/import preserves per-row outcomes and real evidence;
  withdrawal preserves its stable request ID and REQUESTED/PAID distinction.
- Account/social maintenance distinguishes stored state from provider verification;
  Reel Inbox preserves sender scope/partial207 and genuine DM verification.
- Pastes require explicit public-sharing review; Context Store remains private;
  legacy course uploads and attachment registration are separate reviewed steps.
- Webinar invite acceptance is matching-email/self-only; verify complete bounded
  CSV bytes through discovered binary export, not a JSON envelope/preview.
- Editor markers/audio detach/combine/voice replacement and layouts preserve
  project assertions and current-design save. Board assertions must survive batch
  children; a successful save with `liveBoardUpdated:false` must not auto-replay.
- Saved teleprompter/scripts/assets/podcast dashboard state is not live transport,
  capture, byte upload or processing completion. Follow the owning domain's
  explicit missing/human/operational boundaries.

## Mounted continuation verification

- Discover the26 mounted renderer names separately from saved HTTP workflows.
  Pin explicit tab plus script/session/board identity and verify its actual URL:
  teleprompter player, podcast dashboard, connected studio, board or video editor.
  An inventory from another view does not authorize dispatch.
- Recognized non-timeline media controllers resolve readiness without timeline
  autosave recovery, delayed `editor.save` or media-health probing. A stale
  timer must recheck the current addressed renderer; freeze frame retains normal
  timeline save integration. Board apply still requires separate board save.
- Inspect native processing through upload/finalization and completed GIF jobs;
  start/retry/resume/reprocess acceptance alone is not delivery. Review actual
  SVG/PDF/editable-PPTX bytes and fidelity warnings, not renamed screenshots.
- Spreadsheet prepare/apply is not editable PPTX import. Recording start and
  stop/chunk/upload finalization remain explicit missing operations; device/
  quality selection does not imply recording or permission consent.
